# Council artifact — Headroom tray-icon readability audit (2026-09-08)

## The problem (owner's words)
"A lot of the variants are still just too little / not readable when usage is close to 0, etc. We need an audit and a real fix." Headroom is a Windows tray app; each tray icon is a square painted by us at the shell's small-icon size: **16 px at 100 % DPI** (the owner's machine), 20 @125 %, 24 @150 %, 32 @200 %. Icons are monotone by default (white on a dark taskbar, near-black on a light one), optionally one of eight named colours, and tinted amber/red at the user's warning/critical lines.

## What the painter does today (src/tray_paint.rs)
- Coverage canvas, 4x4 supersampling; shapes: rect, disc, ring_arc, text.
- Text: a 3x5 pixel font (digits + A–Z), cells snapped to whole/half pixels (`snap_text_scale`: floor to 0.5 steps, never above the fitted bound, floor 1 px/cell). Three chars max.
- Styles (`TrayIconStyle`): Number (digits fill the square) · Bar (horizontal bar, track alpha 0.28, 0.9-alpha edge frame ~1 px, fill 1.0) · Column (same, vertical) · Ring (r_out 0.47n, r_in 0.35n; 270° arc from 225°; track alpha 0.30; fill alpha 1.0; optional text inside, corner-capped to r_in) · Letters (label drawn at full size at alpha 0.30, re-drawn solid from the bottom up to the percentage) · TextBar (big text over a bottom bar: bar height max(3, 0.19n), track 0.30, fill 1.0; DEFAULT for new icons) · Rundown (one thin bar per enabled provider, track 0.28, fill 1.0; a provider with nothing = 0.16 outline).
- Marks (`TrayIconMark`): the percent digits, or a 1–3 character label (provider initials by default), or none; placement: inside the ring, in a caption band above bar/column/number, above the letters; TextBar's text IS the mark.
- `measure`: Used (default) or Remaining (100 − used) — same shapes, inverted number.
- Alert tint replaces the monotone colour at ≥warn (amber) / ≥critical (red) if enabled per icon.
- Logo (static gauge) exists as a separate mode.

## Constraints
- The square is what it is: 16 px at 100 % DPI is the common case (owner's), and Windows gives no bigger slot.
- Monotone is the default by design (owner ruling); colour is opt-in per icon; the alert tint is reserved for warn/critical and must stay unmistakable.
- Both taskbar tones must work (Windows light theme = light taskbar).
- Text is our 3x5 font; anything below 1 px/cell is not drawn.
- The renderer is pure Rust, easy to change; every layout is unit-tested by counting pixels. Changes to the settings enum bump a schema version (cheap).
- Several icons can be shown at once (one per provider), so "which is which" matters as much as "how much".

## Questions for the seat
1. Audit: for each style at 16 px, rate legibility at 0 %, 5 %, 50 %, 95 %, 100 % on both taskbar tones. Which variants effectively vanish at low usage, and why (alpha, thickness, size, contrast)?
2. Concrete fixes, ranked by impact/effort, implementable today in the painter: minimum-visible track alpha (what value?), solid frames/edges regardless of fill, an "empty state" that still shows a shape, whether Remaining should be the default measure (filled = headroom left), simplification rules below 20 px, contrast rules per tone (e.g. track alpha differs on light vs dark), stroke thickness minimums, whether text-only styles should gain a fill cue and shape-only styles a text cue.
3. Which styles should be removed, merged, or renamed so the menu offers fewer but better options? What should the default be, and with which mark?
4. Anything that makes several icons tell apart at a glance beyond the label (shape family per provider? position cue?).
Answer with a ranked findings list (impact: high|med|low, confidence 0–20) and a change list with the exact geometry/alpha numbers you propose.
